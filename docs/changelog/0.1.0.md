# 0.1.0

Not yet released. The first extraction, from the National Geographic _Food for
Tomorrow_ explore globe, which still consumes this arithmetic.

[Compare on GitHub](https://github.com/fndvit/VizVit-Chart/commits/main) ·
[#1](https://github.com/fndvit/VizVit-Chart/pull/1)

## Added

- **The class-band scale**, at `@vit-foundation/chart/scale`. `classColors`
  samples a ramp in LAB at `i / (k − 1)`; `classOpacities` spreads `k` alphas
  across `[min, max]`. Both run light/thin → dark/solid, so the two channels
  reinforce each other. This is the agreement the package exists to hold: a
  renderer and a legend given the same ramp and the same `k` cannot disagree
  about what a class is.
- **`<PercentLegend>`**, at `@vit-foundation/chart/PercentLegend.svelte`. A ramp
  bar from `0` to the domain max, with class breaks drawn as hard-edged bands or
  as ticks, and the break values written along the axis wherever they fit. The
  colour channel (`breaks`) and the alpha channel (`opacity`) are composited
  independently, so mismatched break sets still render correctly. `flat` is the
  opacity-only variant.
- **The legend's arithmetic as its own module**, at
  `@vit-foundation/chart/legend`: `axisMaxOf`, `maxLabelOf`, `formatBreak`,
  `bandEdges`, `pickLabels`, `ticksOf`, `barGradient`, and the `PercentBarSpec`,
  `OpacitySpec` and `Tick` types. No Svelte and no DOM, so a bar you draw
  yourself — in SVG, on a canvas, under another framework — can be the same bar.
- **Label thinning that reads the rendered width.** Every break keeps its tick;
  at most `maxLabels` values are written out, chosen as the largest
  non-overlapping subset with the widest narrowest gap across the row, so the
  values spread over the axis instead of clumping at one end. The component
  measures itself and hands the width to the arithmetic.
- **Three narrow subpaths** — `./scale`, `./legend`, `./PercentLegend.svelte` —
  so a leaf component imports the one symbol it needs, and the two
  pure-arithmetic modules stay importable from plain Node. See
  [the reference](../reference.md).
- **A packaging boundary test.** `libraryBoundary.test.ts` fails the build on a
  dependency beyond `chroma-js` and `svelte`, a bare relative specifier, map or
  dataset vocabulary in executable code, and any CSS-framework class. It earned
  its place immediately: it caught bare `./percentBar` specifiers that
  `svelte-package` emits verbatim and Node cannot resolve — which `publint`
  passed.

## Changed

- **The package is `@vit-foundation/chart`**, renamed from
  `@vit-foundation/vizvit-chart`, and versioned `0.1.0` rather than `0.0.4`.
  `0.0.3` contained only the `ExampleChart` scaffold; this is the first release
  with a library in it.

  **Upgrading:** change the dependency name and the import specifier. Nothing
  else moved — `ExampleChart` is still exported from the barrel under the same
  name. The old package stays on npm at `0.0.3` and will not be updated.

- **The legend is themed with CSS custom properties**, not utility classes. It
  arrived carrying Tailwind utilities and the host application's own design
  tokens (`text-story-dark`, `text-xxs`), which made it unstyleable anywhere
  else. Presentation is now plain CSS with `--vit-legend-*` hooks and real
  fallbacks, so the component renders standalone and a consumer restyles it
  without adopting a framework. See
  [theming](../legend.md#theming) for the seven properties.

## Removed

Nothing. `ExampleChart` is untouched and still exported from the barrel.

## Other (dependencies, CI, tools…)

- `chroma-js` is the package's one runtime dependency; `svelte` ^5 is its one
  peer, and only the component needs it.
- **65 tests added**, bringing the suite to 66: 11 for the scale, 28 for the bar
  arithmetic, 20 for the component in a real browser, and 6 for the packaging
  boundary. `classBands` previously had no test of its own — it was reached only
  transitively, through a component test that parsed a CSS gradient string.
- The component suite is `*.svelte.test.ts` in the real-browser `client` Vitest
  project rather than the jsdom setup it arrived with, because label thinning
  depends on a genuinely measured width. Five assertions widened their tolerance
  as a consequence: Chrome serializes a percentage to about six significant
  digits, so `26.027777777777779%` reads back as `26.0278` and a `5e-7`
  precision fails on a correct value. Three decimals on an axis percentage is
  finer than anything visible.
- Verified end to end by packing the tarball, installing it into a clean project
  and importing both `.ts` subpaths from plain Node.

## Notes for consumers

- **`k` classes, `k − 1` breaks.** Everything here counts classes. The `k` you
  hand the renderer is the `breaks.length + 1` you handed the legend — that
  identity is the contract, and it is the one thing to get right.
- **The two `.ts` subpaths run in plain Node.** The barrel re-exports
  components, so importing `@vit-foundation/chart` itself needs a Svelte-aware
  bundler. Reach for it only from an app that has one.
- **`breaks` are an input.** This package has no opinion on how a domain is
  cut — ckmeans, quantiles or an authored banding all work, and none of them
  lives here.
- **`classOpacities` returns floating-point values**, so `classOpacities(5, 0.2, 1)[2]`
  is `0.6000000000000001`. Compare with a tolerance.
- Before 1.0.0 the surface is still settling, and a MINOR may narrow it.
